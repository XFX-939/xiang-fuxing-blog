最近我在自己的 MacBook Pro 上安装了 Clash Verge Rev，并导入了一份已经准备好的自建节点配置。

这次我刻意把“安装”“启用”和“测试”拆成了三个阶段：先把客户端与配置准备好，再安装 TUN 所需的系统服务，最后才考虑是否接管网络。这样做的好处是，每一步造成的变化都比较清楚，出现问题时也更容易恢复。

本文记录的是前两个阶段。截至文章完成时，我已经安装客户端、导入配置并安装后台服务，但**没有开启系统代理，没有开启 TUN，也没有进行连接或出口测试**。

## 一、先确认协议与客户端是否匹配

我使用的自建节点并不是 macOS“系统设置 → VPN”里可以直接填写的 IKEv2，而是 VLESS、XTLS Vision 与 REALITY 的组合，由 sing-box 服务端提供。

因此，Mac 上需要安装能够识别相应 Mihomo 配置的客户端。综合图形界面、Apple Silicon 支持和配置兼容性后，我选择了 Clash Verge Rev。

这里最容易踩的坑，是把所有“VPN”都当成 macOS 原生 VPN。实际上，不同协议需要不同客户端。先确认协议，再选软件，比安装以后反复排查更省时间。

## 二、从官方渠道下载 Apple Silicon 版本

下载前，点击屏幕左上角的苹果图标，进入“关于本机”，确认芯片类型：

- Apple M 系列芯片选择 Apple Silicon，也就是 ARM64 或 aarch64 版本；
- 较早的 Intel Mac 选择 Intel 或 x64 版本。

我的 MacBook Pro 是 Apple Silicon，因此下载了 ARM64 版本。本次实际安装的是 Clash Verge Rev 2.5.2。

安装包只从 [Clash Verge Rev 官方 GitHub Releases](https://github.com/clash-verge-rev/clash-verge-rev/releases) 获取，不使用第三方网盘或重新打包版本。下载 DMG 后，将应用拖入“应用程序”文件夹，再从“应用程序”中启动。

为了确认下载文件没有被替换，我还做了两项检查：

1. 用 SHA-256 对照官方 Release 页面提供的校验值；
2. 确认 macOS 接受应用签名与公证状态。

SHA-256 可以在终端中这样查看：

```bash
shasum -a 256 "/path/to/Clash Verge.dmg"
```

命令得到的值应与对应版本、对应架构的官方校验值完全一致。不要把其他版本的校验值拿来比较。

## 三、准备本地 Mihomo YAML 配置

我已经有一份用于自建 VLESS/REALITY 节点的 Mihomo YAML，因此不需要在客户端里逐项填写服务器信息。

一个可用于日常使用的完整配置，通常不只有节点本身，还会包含：

- 代理节点与代理组；
- DNS 设置；
- 国内、局域网与代理目标的分流规则；
- TUN 等运行参数。

只有一条 VLESS 分享链接时，也许可以完成单节点导入，但它不等于已经具备 DNS、TUN 和分流策略的完整配置。

配置文件通常含有服务器地址、端口、UUID、REALITY 公钥、短 ID 等接入材料。这些内容相当于访问凭据，不能放进公开 GitHub 仓库，也不应上传到在线转换网站、公开云笔记或聊天截图中。本文只描述操作流程，不展示任何真实配置值。

## 四、“订阅”入口在哪里

第一次打开 Clash Verge Rev 时，我也没有立即找到本地配置的导入位置。当前版本里有两个入口：

1. 在首页的“订阅”卡片中点击“导入订阅”；
2. 点击左侧菜单中的“订阅”。

进入“订阅”页面后，可以选择本地 YAML，也可以直接把配置文件拖入窗口。官方文档说明，本地文件导入后会被复制到应用的 profiles 目录，因此以后移动原文件不会让已经导入的配置立即失效。具体方式可参考 [Clash Verge Rev 的订阅导入说明](https://www.clashverge.dev/guide/profile.html)。

我导入的是日常分流版本，而不是用于故障排查的“全部代理、全部 UDP 拒绝”基线。导入后，先确认配置名称、代理组和规则模式，不要因为看到节点名称就认为网络已经被接管。

需要特别区分三个状态：

- **导入配置**：文件已经进入客户端；
- **加载配置**：Mihomo 可以读取节点、规则与 DNS 设置；
- **接管网络**：系统代理或 TUN 开关已经开启。

前两个状态都不等于第三个状态。

## 五、系统代理与虚拟网卡模式有什么区别

Clash Verge Rev 首页的“网络设置”中有“系统代理”和“虚拟网卡模式”两个选项。它们解决的问题并不完全相同。

| 对比项 | 系统代理 | TUN 虚拟网卡模式 |
| --- | --- | --- |
| 工作方式 | 修改 macOS 的 HTTP、HTTPS、SOCKS 代理设置 | 创建虚拟网卡并调整系统路由与 DNS |
| 覆盖范围 | 主要覆盖遵循系统代理的浏览器和应用 | 可以覆盖更多不读取系统代理的应用与命令行程序 |
| 系统影响 | 相对较小，开关简单 | 影响范围更大，涉及路由、DNS 和网络扩展 |
| 是否需要服务模式 | 通常不需要 | 需要后台服务或管理员模式 |
| 排障难度 | 较低 | 较高，需要同时检查规则、DNS 和其他网络工具 |

如果只是浏览器访问，系统代理通常更容易理解和排查。如果希望终端、原生应用以及更多流量统一遵循规则，TUN 更合适。

不过，TUN 与其他 VPN、WARP、Tailscale、网络过滤器或自定义 DNS 同时开启时，可能发生路由和 DNS 冲突。排障时最好一次只保留一套网络接管工具。

## 六、安装 TUN 所需的后台服务

我最终决定使用虚拟网卡模式，但没有立刻打开 TUN，而是先安装它依赖的服务。

入口位于：

**首页 → 网络设置 → 虚拟网卡模式 → 安装服务**

点击“安装服务”后，macOS 可能要求 Touch ID 或管理员密码。这一步是在授权 Clash Verge Rev 安装一个具有管理员权限的后台辅助服务，使 Mihomo 以后能够创建 TUN、修改路由和处理 DNS。

安装成功后，界面会出现两个明显变化：

- “安装服务”按钮变成“卸载服务”；
- 原本灰色不可用的 TUN 开关变为可操作状态。

这两个变化只能证明服务已经安装成功，**不代表 TUN 已经开启**。我确认状态后仍然让开关保持关闭，也没有打开系统代理。

官方说明中将 `clash-verge-service` 定义为独立于客户端界面的后台进程，用于以管理员权限拉起相关内核。可以在 [Clash Verge Rev 名词解释](https://www.clashverge.dev/guide/term.html) 中查看服务模式的说明。

## 七、开启 TUN 前需要知道的事情

TUN 会接管比系统代理更多的流量，因此正式开启前最好先准备好回退方式：

1. 确认配置来源可信，并保留原始配置备份；
2. 确认使用“规则”模式以及正确的代理组；
3. 确认局域网、国内网站和需要代理的目标如何分流；
4. 暂时关闭其他 VPN、TUN 与网络过滤工具；
5. 记录关闭 TUN 和卸载服务的入口。

Clash Verge Rev 的 [macOS 常见问题](https://www.clashverge.dev/faq/macos.html) 提到，开启 TUN 时客户端会暂时修改系统 DNS，以保证流量进入 Mihomo；关闭 TUN 后会恢复原来的系统 DNS。因此，看见 DNS 在 TUN 开关切换时发生变化，并不一定是异常。

如果启用后出现无法上网、域名解析失败或局域网设备无法访问，第一步应是关闭 TUN 和系统代理，恢复直连，再查看刚刚产生的日志。不要在故障位置尚未明确时同时修改多处 YAML。

## 八、本次实际操作的最终状态

这次安装结束时，电脑上的状态是：

- Clash Verge Rev 2.5.2 已安装；
- 本地 Mihomo YAML 已成功导入；
- 代理模式保持为“规则”；
- TUN 所需后台服务已安装；
- “安装服务”已经变为“卸载服务”；
- 系统代理保持关闭；
- TUN 虚拟网卡保持关闭；
- 没有进行节点连通性、出口 IP 或地区测试。

我没有在安装服务后顺手打开所有开关。安装后台服务是一次系统权限变更，而开启 TUN 又是另一次网络状态变更，把两者分开更便于确认结果。

## 常见问题

### 为什么导入以后没有开始代理？

因为导入只是在客户端中加入配置。还需要确认配置、代理组和规则，并主动开启系统代理或 TUN，网络流量才会被接管。

### 为什么 TUN 开关是灰色的？

通常是因为服务模式尚未安装或没有正常运行。安装成功后，“安装服务”会变成“卸载服务”，TUN 开关也会恢复可用。

### 安装服务是否等于连接节点？

不等于。服务只是提供以后管理虚拟网卡、路由和 DNS 的权限。只要系统代理与 TUN 都保持关闭，安装服务本身不会自动完成代理连接测试。

### 日常使用应该选“全局”还是“规则”？

日常使用更适合“规则”模式，让不同目标按照配置分流。“全局”会让更多流量统一经过代理，适合短时排障，不宜在没有明确需要时长期使用。

## 总结

这次过程可以概括为：

**确认协议与芯片架构 → 从官方 GitHub 下载并校验客户端 → 安装 Clash Verge Rev → 从“订阅”页面导入本地 YAML → 区分系统代理和 TUN → 安装后台服务 → 保持网络开关关闭。**

对网络工具来说，“已经安装”与“已经接管网络”是两件事。把下载、导入、授权、启用和测试拆开处理，既能减少意外断网，也能让后续排障有更清楚的边界。
